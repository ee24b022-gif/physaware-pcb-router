# Congestion model validation

## Decision

**Do not integrate congestion predictions into `pcbroute` routing decisions.** Keep the model and CLI experimental until it beats the baseline on held-out boards.

The original repository checkout was not available in the current sandbox: the referenced GitHub URL requires authentication. The validation therefore used the model contract recorded by the prior task (`CongestionPredictionMLP`, `17 → 32 → 1`) and its documented 17-feature schema. The harness is a reproducible fallback validation, not a claim that the inaccessible private checkout was executed directly.

## Protocol

- 50 training boards, seeds `1000–1049`.
- 50 disjoint held-out boards, seeds `2000–2049`.
- Training used only the training split.
- Labels were generated by a deterministic routed-grid capacity/demand congestion simulator with independent topology/obstacle interaction noise.
- Baseline: constant predictor equal to the training-set target mean.
- Metrics: mean absolute error (MAE) and root mean squared error (RMSE).
- Integration gate: the model must improve both MAE and RMSE on the held-out split.

## Results

| Predictor | MAE | RMSE |
|---|---:|---:|
| 17→32→1 congestion MLP | 0.059458 | 0.077737 |
| Mean predictor baseline | 0.010454 | 0.020124 |

The MLP is worse than the mean predictor on both metrics. It therefore **fails the integration gate**.

## Routing impact

No routing code or net-ordering policy was changed. Congestion predictions must not be used to choose routing order, rank candidate paths, or modify congestion penalties. The deterministic router remains authoritative.
